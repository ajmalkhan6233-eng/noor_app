# noor Scope Discipline

## Rule
Only build what was explicitly asked for in the current instruction.
If something adjacent seems worth doing (a competitor pattern, a
related fix, an improvement noticed along the way), name it and ask
rather than building it silently — even if it seems small, even if it
seems obviously good.

## Why this matters here specifically
This project has real, deliberate cut decisions (community/masjid
feature, streak tracker, Hajj/Umrah guide) made explicitly, in
writing, in CLAUDE.md's Deferred section. A pattern noticed during
competitor research (like a weekly tracker chart) can look like a
small addition but actually reintroduce something already decided
against. Silently "helping" by adding it back is a real risk, not a
convenience.

## In practice
- Finish exactly what was asked, verify it, commit it.
- If something else seems worth flagging, say so as a suggestion in
  the report-back, not as work already done.
- Check CLAUDE.md's Deferred section before adding anything that
  resembles a previously-cut feature, even partially.
